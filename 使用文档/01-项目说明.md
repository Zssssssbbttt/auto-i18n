# toI18n — Vue 2/3 国际化自动化工具 · 项目说明

> 本文回答一个问题：**这是什么**。
> 配套阅读：《02-使用手册》（怎么用）、《03-脚本运行说明》（做了什么、替你想了什么）。

---

## 1. 这是什么

做 Vue 国际化，麻烦的不是接入 vue-i18n，而是把页面里成片的中文改成 `$t('key')`，再把语言包对齐。

这个工具把「扫描、翻译、预览、替换」串成一条流水线。交付物是一个文件：**`toI18n.cjs`**，放到任意目录直接运行，只需配置目标项目路径即可，零额外依赖。

**同时支持 Vue 2 和 Vue 3**，自动识别或手动指定 Vue 版本，对应适配 Element UI（Vue 2）/ Element Plus（Vue 3）/ Vant（Vue 3 移动端）组件库。

---

## 2. 为什么要做

### 2.1 实际问题

| 痛点 | 真实情况 |
| --- | --- |
| 接 vue-i18n | 很快 |
| 硬编码中文改成 `$t()` | 页面一多就容易漏，也费时间 |
| 同一句中文对应同一个 key | 人工很难保持一致 |
| 再加一门语言 | 容易动到已有翻译，又得整包过一遍 |
| Vue 2 / Vue 3 项目并存 | 两套 API 差异大，人工改造易出错 |

框架接入不难，真正难的是存量改造和一致性维护。

### 2.2 为什么不用正则硬扫

正则只能找到「这行有中文」，分不清：

- 是用户能看见的文案，还是 class、注释、业务数据
- 是不是已经包在 `$t()` 里了
- 动态绑定、三元表达式、方法参数该怎么改才安全

改错就直接炸页面。所以工具用 **AST（抽象语法树）** 定位——像编译器一样理解代码结构，而不是靠字符串匹配猜。

### 2.3 落地原则

全自动一键改完不现实，风险太大。做法是：

1. 白名单里的展示文案：自动换
2. 拿不准的：标出来，人来看
3. 真正改文件前：必须先预览确认

## 4. Template 与 Script 分别处理

### 4.1 Template 解析（`<template>` 部分）

模板用 Vue 编译器解析成 AST，再按节点类型分类处理。所有处理受 `i18n.config.js` 中的白名单/黑名单控制。

**会自动替换的情况：**

| 类型 | 原始写法 | 替换后（Vue 3） | 触发条件 |
| --- | --- | --- | --- |
| 静态属性 | `<el-input label="申请人" />` | `<el-input :label="$t('common.applicant')" />` | 属性名在 `translateAttributes` 白名单且不在 `ignoreAttributes` 黑名单 |
| 动态属性 | `:placeholder="status === 1 ? '已通过' : '待审核'"` | `:placeholder="status === 1 ? $t('common.passed') : $t('common.pending')"` | `:attr` 或 `v-bind:attr`，属性名在白名单，表达式内含中文 |
| 文本内容 | `<el-button>确认删除</el-button>` | `<el-button>{{ $t('common.confirmDelete') }}</el-button>` | 标签间的纯文本节点，含中文 |
| 插值表达式 | `{{ status === 1 ? '启用' : '禁用' }}` | `{{ status === 1 ? $t('common.enable') : $t('common.disable') }}` | `{{ }}` 内含中文字符串 |

> 模板部分 Vue 2 与 Vue 3 替换结果一致——两者都通过全局注册的 `$t` 访问，只是注册位置不同（Vue 2 挂到原型、Vue 3 挂到全局属性）。

**会自动跳过的情况：**

| 原始写法 | 跳过原因 |
| --- | --- |
| `<div class="中文类名">` | `class` 在 `ignoreAttributes` 黑名单 |
| `v-if="status === '已通过'"` | 指令名不是属性绑定，无法确定属性名 |
| `@click="handle('确认')"` | 事件绑定，不在白名单 |
| `{{ $t('already.translated') }}` | 已被 `$t()` 包裹，避免二次替换 |

**会被标记为「特殊-未处理」的情况：**

| 类型 | 示例 | 原因 |
| --- | --- | --- |
| 不在白名单的属性 | `empty-text="暂无数据"` | 自定义组件属性，可能也需要翻译但需确认 |

### 4.2 Script 解析（`<script>` / `<script setup>` 部分）

脚本用 Babel 解析 JS/TS 为 AST，支持 `.vue` 文件里的 `<script>` 块，以及独立的 `.ts` / `.js` 文件。配置项 `scanScript` 控制是否扫描脚本中的中文（总开关）。

脚本解析通过两种机制覆盖不同场景，**并行生效、互不冲突**：

- **`scriptTargets`** — 处理变量声明中的展示文案（表格列定义、表单配置等对象属性）
- **`translateMethods`** — 处理方法调用中的提示文案（ElMessage、确认框等用户可见消息）

#### 机制一：变量声明正向匹配（`scriptTargets`）

精确指定要翻译的**变量名 → 属性名数组**：

```js
scriptTargets: {
  columns: ['label', 'title'],   // 只翻译 columns 中 label 和 title 属性
  rules: ['message'],             // 只翻译 rules 中 message 属性
  options: [],                    // [] 表示翻译该变量内所有中文（全量递归）
}
```

**不在配置中的变量不会被翻译。** 这避免了「一刀切」导致的误替换。

| 场景 | 原始写法 | 替换后（Vue 3） | 替换后（Vue 2） |
| --- | --- | --- | --- |
| 对象属性 | `{ label: '请输入名称' }` | `{ label: $t('common.pleaseEnterName') }` | `{ label: this.$t('common.pleaseEnterName') }` |
| 三元表达式 | `{ label: cond ? '是' : '否' }` | `{ label: cond ? $t('k1') : $t('k2') }` | `{ label: cond ? this.$t('k1') : this.$t('k2') }` |
| 数组嵌套 | `[{ label: '中文' }]` | 递归处理每个元素 | 同左 |
| 深层嵌套 | `{ children: { label: '中文' } }` | 递归进入嵌套对象 | 同左 |

> **Vue 2 / Vue 3 的 script 替换差异**：Vue 3 使用模块级导出的 `$t('key')`；Vue 2 使用实例方法 `this.$t('key')`（vue-i18n@8 的 API 风格），工具按检测到的 Vue 版本自动选择格式。

**接口数据自动跳过：** 当变量初始化是函数调用（非 ref/reactive）或 await 表达式时，认为数据来自接口返回，自动跳过不翻译：

```js
const data = fetchData()                // 跳过 — 接口数据
const list = await getList()            // 跳过 — 接口数据
const form = ref({ label: '中文' })     // 处理 — Vue 响应式声明
const columns = [{ label: '中文' }]     // 处理 — 静态声明
```

**响应式包裹（`scriptReactive`）：** 当 `scriptReactive: true` 时，对纯文本值 `const` 声明的翻译目标自动包裹 `computed(() => ...)`，使翻译结果随语言切换响应式更新。`let` 变量不包裹，`ref()`/`reactive()` 包裹的变量不处理（本身已具备响应式）。

#### 机制二：方法调用白名单（`translateMethods`）

白名单内的函数调用参数中的中文自动翻译，支持通配符。**默认值按 Vue 版本自动区分**：

| Vue 版本 + 组件库 | 默认 translateMethods |
| --- | --- |
| Vue 3 + Element Plus | `ElMessage.*`、`ElMessageBox.*`、`ElNotification.*`、`alert`、`confirm`、`showWarningMessage` |
| Vue 3 + Vant | `Toast`、`Toast.*` |
| Vue 3 + 无组件库 | `[]` |
| Vue 2（不区分组件库） | `this.$message.*`、`this.$confirm`、`this.$alert`、`this.$prompt`、`this.$notify.*` |

| 类型 | 原始写法 | 替换后（Vue 3） |
| --- | --- | --- |
| 白名单方法调用 | `ElMessage.warning('请先选择数据')` | `ElMessage.warning($t('common.pleaseSelectData'))` |
| 通配符匹配 | `ElMessage.success('操作成功')` | `ElMessage.success($t('common.operationSuccess'))` |

**会自动跳过的情况：**

| 原始写法 | 跳过原因 |
| --- | --- |
| `form.status = '已通过'` | 成员表达式赋值，自动识别为数据值而非展示文本 |
| `import { ref } from 'vue'` | import 声明 |
| `type Status = '已通过'` | TS 类型注解 |
| `console.log('调试信息')` | 不在白名单的方法参数 |
| 变量名不在 `scriptTargets` 中 | 正向匹配——未配置的变量不翻译 |

**会被标记为「特殊-未处理」的情况：**

| 类型 | 示例 | 原因 |
| --- | --- | --- |
| 模板字符串含变量 | `` `共${total}条记录` `` | 变量参数需人工设计 |
| 字符串拼接 | `'完成时间：' + date` | 拼接语序问题需人工处理 |
| 字符串含 HTML 标签 | `'当<b>不是</b>时'` | 避免 AI 翻译破坏 HTML 标签结构 |

## 5. 特殊处理与安全机制

### 5.1 自动标记「需要人工处理」的边界情况

工具将无法安全自动处理的条目单独归类为「特殊-未处理」，标注位置、类型、原因，不自动替换，交由人工逐条确认。含 HTML 标签的字符串（如 `<b>重要</b>提示`）也会被自动检测并标记为特殊项，避免 AI 翻译时破坏标签结构。这类条目会写入日志文件（`logs/i18n-special-<时间戳>.log`）。

### 5.2 翻译阶段也有分类记录

对于符合白名单配置但被特定规则过滤掉的文本（注释中的中文、已有的 `$t()` 调用、纯数字/符号等），翻译阶段同样会分类记录到日志，方便人工复核是否有遗漏。

### 5.3 安全替换策略

- **从后往前按行替换**：先改后面行，前面行号不受影响
- **同行长文本优先**：避免短文本先匹配导致长文本错位
- **列号精确定位**：优先用 AST 提供的列号定位中文，同一行出现相同中文也不会替换错位置
- **自动注入 import**：检测文件是否用了 `$t()` 但缺 import，自动补全；用了 `computed` 也会自动补全对应的 vue import

### 5.4 解析失败可见化

部分 Vue 2 文件使用了 Vue 3 编译器无法解析的旧语法。解析失败的文件以前只是静默跳过、只显示一个错误数字，用户不知道哪些文件没扫到。现在预览输出会**明确列出解析失败的文件路径和原因**，这些文件里的中文由人工处理，不会遗漏。

## 6. 关键技术点

### 6.1 AI 翻译：填空式 JSON + 缺口补齐

**新文本翻译**：AI 为每条中文生成 `module.keyName` 和目标语言翻译。

**新增语言补齐**：当项目已有大量双语翻译后想加第三种语言，工具自动检测「已有 key 但目标语言缺失」的缺口，按缺失语言分组，用带空位的 JSON 模板让 AI 填空：

```json
// 输入（模板）
{"transfer.sponsor": {"th": ""}, "transfer.status": {"th": ""}}
// 输出（AI 填空）
{"transfer.sponsor": {"th": "ผู้สนับสนุน"}, "transfer.status": {"th": "สถานะการโอน"}}
```

AI 只需填空、无需自组织 JSON，大幅降低格式错误概率。返回结果逐条校验，缺失项自动重试（最多 3 次），失败的记入日志。

### 6.2 Key 生成：复用已有翻译

```
已有语言包反向映射（中文 → 已有 Key）
  > 参考语言包反向映射（referenceLocales 配置，本项目优先）
  > AI 生成（根据语义自动生成 module.keyName）
```

同一中文始终映射到同一 key，不会出现重复翻译或不一致。

### 6.3 外部共享语言包（`sharedLocales`）

如果项目使用了多个仓库共享的公共语言包，可通过 `sharedLocales` 配置引入。初始化时会校验共享包完整性，校验通过的共享包被深度合并到 i18n 实例——项目自身翻译优先级高于共享包（项目覆盖共享）。

**共享包校验规则（三条，必须全部通过）：**

1. **路径存在** — 配置的目录路径必须存在
2. **语言文件齐全** — 必须包含源语言和所有目标语言的 `.json` 文件
3. **Key 数量一致** — 各语言文件的 key 数量必须与源语言一致

校验不通过时，交互模式会询问是否继续（跳过共享包），非交互模式自动跳过。

### 6.4 语言包管理边界

- **新增语言自动注册**：每次初始化都会**完整重建** `index.ts`——遍历配置中的全部语言，一次性生成 import、messages 条目和组件库 locale 注册，杜绝漏注册。
- **移除语言自动清理**：从配置删掉某语言后，重建时自然不再生成其注册；语言包 JSON 文件保留不删除，防止误删。
- **手动放置但未配置的语言包**：不处理、不提示，以配置为唯一真相来源。
- **目标语言 key 不对应**：中文有、目标语言缺 → AI 自动补齐；目标语言有、中文没有（僵尸条目）→ 不处理，以 `zh-CN.json` 为唯一结构基准。
- **无 AI 模式不自动生成 key**：未配置 AI 时，未匹配的中文不会写入语言包（避免低质量 key 永久残留），由用户手动添加或启用 AI。

### 6.5 翻译辅助（`typeToString.ts` / `toI18n.ts`）

静态扫描替换只能处理**源码里硬编码的中文**。但有一类中文是接口在运行时返回的——状态名称、下拉选项、审批节点名、按钮权限名等，编译期根本看不到，无法提前替换。为此初始化时在 `locales/` 下生成两个辅助模块：

| 文件 | 导出方法 | 解决的问题 |
| --- | --- | --- |
| `typeToString.ts` | `i18nTypeToString(key)` | `$t()` 返回值在 TS 中的类型是联合类型，赋给要求 `string` 类型的属性/参数时编译报错，此方法强制转成 `string` |
| `toI18n.ts` | `translateText(text)` / `translateArray(arr, keyName)` | 接口返回的中文数据，运行时通过「中文 → key」反向映射查到翻译并返回 |

两者都会在初始化时**自动全局注册**（Vue 3 注册到全局属性、Vue 2 注册到原型），模板和脚本中可直接使用，无需手动 import。详细用法见《02-使用手册》。

## 7. Vue 2 / Vue 3 双版本兼容

### 7.1 版本差异对照

| 维度 | Vue 2 | Vue 3 |
| --- | --- | --- |
| i18n 包 | vue-i18n@8 | vue-i18n v9+ |
| 实例创建 | `new VueI18n({ locale, messages })` | `createI18n({ legacy: false, locale, messages })` |
| 全局注册 | `Vue.prototype.$t = $t` | `app.config.globalProperties.$t = $t` |
| UI 库 | Element UI | Element Plus / Vant |
| 语言同步 | 手动切换 | 自动同步（watch + 拦截 install） |
| script 中替换格式 | `this.$t('key')` | `$t('key')` |
| translateMethods 默认 | `this.$message.*` 等（不区分 UI 库） | `ElMessage.*` / `Toast.*`（按 UI 库） |

**版本检测优先级**：配置文件显式指定 `vueVersion` > 读取项目 `package.json` 中 vue 依赖版本 > 默认 Vue 3。

**依赖自动安装**：初始化时自动检查项目是否有 `vue-i18n` 依赖，缺失则按版本安装（Vue 2 → `vue-i18n@8`，Vue 3 → `vue-i18n`），自动识别 npm / yarn / pnpm 包管理器。

### 7.2 生成的 locales/index.ts 模板

- **Vue 2 + Element UI**：`new VueI18n()` 实例 + Element UI locale 动态导入（所有配置语言）+ 手动切换同步组件库语言。
- **Vue 3 + Element Plus**：`createI18n({ legacy: false })` + Element Plus locale 动态导入（所有配置语言）+ 自动同步。
- **精简模板（Vant / 无组件库）**：仅 vue-i18n 核心配置，无 UI 库耦合。

### 7.3 UI 组件库适配

工具根据 `uiLibrary` 配置自动适配不同 UI 库，生成对应的 i18n 配置模板，并自动设置相应的翻译方法白名单。

| uiLibrary | 适用场景 | 自动设置 |
| --- | --- | --- |
| `element-ui` | Vue 2 PC 端 | Element UI locale 集成，translateMethods 默认 `this.$message.*` 等 |
| `element-plus` | Vue 3 PC 端 | Element Plus locale 集成，translateMethods 默认 `ElMessage.*` 等 |
| `vant` | Vue 3 移动端 | 精简模板，translateMethods 默认 `Toast.*` |
| `none` | 无组件库 | 仅 vue-i18n 核心配置，translateMethods 默认空 |

Element Plus 集成做了两件事确保组件库语言与项目语言始终一致：**监听语言变化自动切换** + **在 `app.use(i18n)` 时自动注入组件库语言上下文**。
