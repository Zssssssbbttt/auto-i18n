# toI18n — Vue 2/3 国际化自动化工具 · 脚本运行说明

## 1. 运行会产出什么

脚本运行后，会在三个层面留下产物：

### 1.1 控制台打印

- 每一步的进度（`[1/4]`、`[2/4]` …）与结果统计
- 逐文件展示将要做的每一项改动（原文本 → 替换结果）
- 已匹配 / 未匹配 / 需人工处理，三类条目分开展示
- 翻译统计：新增翻译条数、缺口补齐条数、失败批次

### 1.2 日志文件（`logs/` 目录）

| 日志 | 内容 |
| --- | --- |
| `i18n-special-<时间戳>.log` | `-s` / `-d` 扫描时标记为「特殊-未处理」的条目（模板插值、字符串拼接、含 HTML 标签等），需人工处理 |
| `i18n-gap-<时间戳>.log` | `-g` 盲区扫描结果：所有含中文的属性/文本（不受白名单限制），用于定位配置遗漏 |
| `i18n-translate-unmatched-<时间戳>.log` | `-t` AI 翻译时未处理的条目（特殊文本、AI 未返回、Key 无效、失败批次） |

### 1.3 语言包与源码

- **语言包文件**（`src/locales/`）：`zh-CN.json`（中文 → key）、各目标语言 JSON、`index.ts`、`typeToString.ts`、`toI18n.ts`、`useI18n.ts`
- **源码改动**：`.vue` / `.ts` / `.js` 中的中文替换为 `$t('key')`，并自动补 import
- **`main.ts` 改动**：补全 i18n 引入、全局 `$t` 注册、`app.use(i18n)`。Vue 3 项目额外注入 `@vnet/i18n` 的公共组件语言包合并代码（`getComponentMessages` + `mergeLocaleMessage` + `setI18nInstance`），使 FlowProcess 等公共组件随项目语言切换

> 只有 `-s` / `-a` / 交互模式的替换步骤会**真正修改源码**；`-d`（预览）和 `-t`（翻译）不碰源码。

## 2. 扫描与匹配规则

### 2.1 扫描分类

所有扫描到中文的地方，被归为三类：

| 类别 | 含义 | 处理 |
| --- | --- | --- |
| 已匹配 | 中文在语言包里已有对应 key | 替换为 `$t('key')` |
| 未匹配 | 中文不在语言包里 | `-t` 时 AI 生成 key 并翻译；`-s` 时不替换、不写语言包 |
| 特殊 | 模板插值 / 字符串拼接 / 含 HTML 标签 | 不替换，单独列出，人工处理 |

### 2.2 跳过规则（优先级从高到低）

脚本不是见到中文就翻译，而是按下面的优先级依次过滤：

1. `ignoreAttributes` 黑名单属性（如 `class`、`name`、`id`）
2. 不在 `translateAttributes` 白名单的属性
3. 不在 `translateMethods` 白名单的方法参数
4. `exclude` 中排除的文件
5. 变量名不在 `scriptTargets` 中的变量声明（正向匹配）
6. 变量初始化为非 ref/reactive 的函数调用或 await 表达式（判定为接口数据）
7. 注释、import 声明、TS 类型注解
8. 已有的 `$t()` 调用（避免二次替换）
9. 纯数字 / 英文 / 符号字符串

### 2.3 Template 解析规则（`<template>` 部分）

模板用 Vue 编译器解析成 AST，再按节点类型分类处理。所有处理受 `i18n.config.js` 中的白名单/黑名单控制。

#### 会自动替换的情况

| 类型 | 原始写法 | 替换后 | 触发条件 |
| --- | --- | --- | --- |
| 静态属性 | `<el-input label="申请人" />` | `<el-input :label="$t('common.applicant')" />` | 属性名在 `translateAttributes` 白名单且不在 `ignoreAttributes` 黑名单 |
| 动态属性 | `:placeholder="status === 1 ? '已通过' : '待审核'"` | `:placeholder="status === 1 ? $t('common.passed') : $t('common.pending')"` | `:attr` 或 `v-bind:attr`，属性名在白名单，表达式内含中文 |
| 文本内容 | `<el-button>确认删除</el-button>` | `<el-button>{{ $t('common.confirmDelete') }}</el-button>` | 标签间的纯文本节点，含中文 |
| 插值表达式 | `{{ status === 1 ? '启用' : '禁用' }}` | `{{ status === 1 ? $t('common.enable') : $t('common.disable') }}` | `{{ }}` 内含中文字符串 |

> 模板部分 Vue 2 与 Vue 3 替换结果一致——两者都通过全局注册的 `$t` 访问，只是注册位置不同（Vue 2 挂到原型、Vue 3 挂到全局属性）。

#### 会自动跳过的情况

| 原始写法 | 跳过原因 |
| --- | --- |
| `<div class="中文类名">` | `class` 在 `ignoreAttributes` 黑名单 |
| `v-if="status === '已通过'"` | 指令名不是属性绑定，无法确定属性名 |
| `@click="handle('确认')"` | 事件绑定，不在白名单 |
| `{{ $t('already.translated') }}` | 已被 `$t()` 包裹，避免二次替换 |

> 不在白名单的属性（如 `empty-text="暂无数据"`）**不会**被标记为「特殊」——它们被静默跳过，不会出现在任何输出中。如需定位这些遗漏，使用 `-g` 盲区扫描。

#### 会被标记为「特殊-未处理」的情况

| 类型 | 示例 | 原因 |
| --- | --- | --- |
| 模板字符串含变量 | `` `共${total}条记录` `` | 变量参数需人工设计 |
| 字符串拼接 | `'完成时间：' + date` | 拼接语序问题需人工处理 |
| 字符串含 HTML 标签 | `'当<b>不是</b>时'` | 扫描/预览时标记为特殊，不自动替换 |

### 2.4 Script 解析规则（`<script>` / `<script setup>` 部分）

脚本用 Babel 解析 JS/TS 为 AST，支持 `.vue` 文件里的 `<script>` 块，以及独立的 `.ts` / `.js` 文件。配置项 `scanScript` 控制是否扫描脚本中的中文（总开关）。

脚本解析通过两种机制覆盖不同场景，**并行生效、互不冲突**：

- **`scriptTargets`** — 处理变量声明中的展示文案（表格列定义、表单配置等对象属性）
- **`translateMethods`** — 处理方法调用中的提示文案（ElMessage、确认框等用户可见消息）

#### 机制一：变量声明正向匹配（`scriptTargets`）

精确指定要翻译的**变量名 → 属性名数组**：

```js
scriptTargets: {
  columns: ['label', 'title'],   // 只翻译 columns 中 label 和 title 属性
  rules: ['message'],             // 只翻译 rules 中 message 属性
  options: [],                    // [] 表示翻译该变量内所有中文（全量递归）
}
```

**不在配置中的变量不会被翻译。** 这避免了「一刀切」导致的误替换。

| 场景 | 原始写法 | 替换后（Vue 3） | 替换后（Vue 2） |
| --- | --- | --- | --- |
| 对象属性 | `{ label: '请输入名称' }` | `{ label: $t('common.pleaseEnterName') }` | `{ label: this.$t('common.pleaseEnterName') }` |
| 三元表达式 | `{ label: cond ? '是' : '否' }` | `{ label: cond ? $t('k1') : $t('k2') }` | `{ label: cond ? this.$t('k1') : this.$t('k2') }` |
| 数组嵌套 | `[{ label: '中文' }]` | 递归处理每个元素 | 同左 |
| 深层嵌套 | `{ children: { label: '中文' } }` | 递归进入嵌套对象 | 同左 |

> **Vue 2 / Vue 3 的 script 替换差异**：Vue 3 使用模块级导出的 `$t('key')`；Vue 2 使用实例方法 `this.$t('key')`，工具按检测到的 Vue 版本自动选择格式。

#### 接口数据自动跳过

当变量初始化是函数调用（非 ref/reactive）或 await 表达式时，认为数据来自接口返回，自动跳过不翻译。这是最容易误解的一点——脚本靠初始化方式区分「展示文本」和「接口数据」：

```js
const data = fetchData()                // 跳过 — 函数调用，判定为接口数据
const list = await getList()            // 跳过 — await，判定为接口数据
const form = ref({ label: '中文' })     // 处理 — Vue 响应式声明
const columns = [{ label: '中文' }]     // 处理 — 静态声明
```

这避免了把接口返回的动态数据误改成 `$t()`。

#### 响应式包裹（`scriptReactive`）

当 `scriptReactive: true` 时，对纯文本值 `const` 声明的翻译目标自动包裹 `computed(() => ...)`，使翻译结果随语言切换响应式更新。`let` 变量不包裹，`ref()`/`reactive()` 包裹的变量不处理（本身已具备响应式）。

#### 机制二：方法调用白名单（`translateMethods`）

白名单内的函数调用参数中的中文自动翻译，支持通配符。**默认值按 Vue 版本自动区分**：

| Vue 版本 + 组件库 | 默认 translateMethods |
| --- | --- |
| Vue 3 + Element Plus | `ElMessage.*`、`ElMessageBox.*`、`ElNotification.*`、`alert`、`confirm`、`showWarningMessage` |
| Vue 3 + Vant | `Toast`、`Toast.*` |
| Vue 3 + 无组件库 | `[]` |
| Vue 2（不区分组件库） | `this.$message.*`、`this.$confirm`、`this.$alert`、`this.$prompt`、`this.$notify.*` |

| 类型 | 原始写法 | 替换后（Vue 3） |
| --- | --- | --- |
| 白名单方法调用 | `ElMessage.warning('请先选择数据')` | `ElMessage.warning($t('common.pleaseSelectData'))` |
| 通配符匹配 | `ElMessage.success('操作成功')` | `ElMessage.success($t('common.operationSuccess'))` |

#### 会自动跳过的情况

| 原始写法 | 跳过原因 |
| --- | --- |
| `form.status = '已通过'` | 成员表达式赋值，自动识别为数据值而非展示文本 |
| `import { ref } from 'vue'` | import 声明 |
| `type Status = '已通过'` | TS 类型注解 |
| `console.log('调试信息')` | 不在白名单的方法参数 |
| 变量名不在 `scriptTargets` 中 | 正向匹配——未配置的变量不翻译 |

## 3. key 如何生成

key 的生成遵循「**三级优先**」，能复用就绝不新造：

```
已有语言包反向映射（中文 → 已有 key）
  > 参考语言包反向映射（referenceLocales，本项目优先）
  > AI 生成（根据语义生成 module.camelCase）
```

- 第一级：中文已经在本项目 `zh-CN.json` 里 → 直接用已有 key。
- 第二级：中文在参考语言包里 → 复用参考包的 key，保证跨项目一致。
- 第三级：都没有 → 交给 AI 根据语义生成 `module.keyName`（如「请选择申请人」→ `validation.pleaseSelectApplicant`）。

**查找阶段只做反向映射查询、不猜 key**；新 key 完全交给 AI 生成。这保证同一句中文永远映射到同一 key，不会出现重复翻译或不一致。

## 4. AI 翻译的容错机制

AI 翻译分两类：**新文本翻译**（未在语言包中的中文）和**缺口补齐**（已有 key 但缺目标语言翻译）。其中**缺口补齐**做了多层容错：

1. **填空式 JSON 模板**：让 AI 在现成结构上填空，而不是自己组织 JSON，从源头降低格式错误。
2. **双重格式约束**：请求时显式声明返回 JSON 格式。
3. **逐条校验**：返回结果逐条检查——模板里的每个 key 是否都有非空翻译。
4. **缺失重试（最多 3 次）**：有缺失就把缺失的 key 列表附到下一次请求里重试；3 次后仍缺失，该批标记失败并记日志。
5. **失败不阻断其它批次**：某个批次失败不影响其它批次的翻译，最后一次性写回语言包，保证文件完整性。

> 换句话说：即使 AI 偶发返回不完整，缺口补齐也会自动补一次、补两次、补三次，实在不行才放弃并留下可查的日志，而不是悄悄写个空翻译进去。

> 新文本翻译目前只调一次，失败直接记入 `i18n-translate-unmatched-*.log`，不重试。如需补齐，重新执行 `-t` 即可。

## 5. 不配置 AI 时的流程

当 `ai.enabled: false`（未配置 AI）时：

- **翻译步骤直接跳过**：不会调用任何 AI 接口。
- **`-s` 扫描时**：语言包为空（反向映射为空），所有中文都归「未匹配」→ 不替换。
- **未匹配的中文不会写入语言包**：这是刻意的设计——如果脚本自动生成低质量的序号 key 写进 `zh-CN.json`，这些 key 会被后续判定为「已翻译」，即使之后启用 AI 也无法重写，低质量 key 会永久残留。

**所以无 AI 模式下，你要做的**：要么手动往语言包里补充中文 → key 的翻译，要么启用 AI 翻译。补充后再 `-s`，这些中文就会自动变成「已匹配」并被替换。

## 6. 跑过一次后再扫描会怎样

反向映射**每次运行都从 `zh-CN.json` 重新构建**。这意味着：

- 你手动往语言包里加了新翻译 → 再次 `-d` / `-s` 时，这些中文自动变成「已匹配」。
- 已翻译的中文不会重复翻译；未翻译的（untranslated 为空、缺口为空）→ 脚本直接退出，不调 AI。
- 缺口补齐**只写缺失的语言**，已有翻译零覆盖。

**幂等性**：

- 空项目：缺口检测为空，全部走新增翻译路径。
- 重复执行：没有新中文、没有缺口 → 直接退出，不产生任何副作用。

## 7. 替换策略与安全机制

### 7.1 安全替换策略

脚本在替换时做了几件「细活」，避免改错位置：

- **从后往前替换**：先改后面行，前面行号不受影响。
- **同行长文本优先**：避免短文本先替换破坏长文本。
- **列号精确定位**：优先用 AST 的列号切片匹配，失败才回退到字符串查找。解决「同行相同中文」误替换——例如 `@click="form.taskComment = '同意'"` 与按钮文本 `同意` 并存时，也能各改各的。
- **单引号 / 双引号属性值都支持**（`label='中文'` 和 `label="中文"`）。
- **多行属性值也能替换**。

### 7.2 自动注入 import

替换完成后自动检查并注入缺失的 import 语句：

- `import { $t } from '@/locales'` — 文件使用了 `$t()` 但缺少该 import 时自动补全。
- `import { computed } from 'vue'` — 仅 `scriptReactive: true` 时，检测到 `computed()` 调用但缺少 import 时自动补全。

注入位置：最后一个 import 语句之后。同时支持 `.vue` 文件（在 `<script>` 标签内）和 `.ts` / `.js` 文件。

### 7.3 解析失败可见化

部分 Vue 2 文件使用了 Vue 3 编译器无法解析的旧语法。解析失败的文件以前只是静默跳过、只显示一个错误数字，用户不知道哪些文件没扫到。现在预览输出会**明确列出解析失败的文件路径和原因**，这些文件里的中文由人工处理，不会遗漏。

### 7.4 标记为「特殊-未处理」的边界

以下场景脚本**故意不自动处理**，而是单独列出来让你人工决定：

- 模板字符串含变量插值：`` `共${total}条记录` `` —— 需要人工设计参数。
- 字符串拼接：`'完成时间：' + date` —— 语序问题，机器翻大概率不通顺。
- 含 HTML 标签的字符串：`'当<b>不是</b>时'` —— 扫描/预览时标记为特殊，不自动替换。

这些会写入 `logs/i18n-special-<时间戳>.log`，并单独列在预览区。

## 8. 边界情况与设计思考

### 8.1 数据值 vs 展示文本（最核心的风险点）

工具无法百分之百判断一个中文字符串最终是「给用户看」还是「提交给后端」：

- **Template 侧**：`el-input` 的 `label="申请人"` 是展示文本（该翻译），`el-radio` 的 `label="已通过"` 是提交给后端的值（**不该翻译**）。当前脚本只看属性名，不区分组件标签名——这是已知局限。
- **Script 侧**：`const tip = '加载失败'` 是展示文本，`form.status = '已通过'` 是数据值。脚本通过检测「成员表达式赋值」（`form.x = '中文'`）自动跳过后者。

**根本原因**：脚本没有后端接口 schema，无法判断值的最终用途。**防御靠三层**：

1. 正向匹配（`scriptTargets`）——只翻译你明确指定的变量
2. 跳过规则——成员赋值、接口数据自动跳过
3. `-d` 预览人工确认——改文件前先看一遍

**给你的建议**：跑 `-d` 时重点看「已通过」「待审核」这类词，确认它们是展示文本再执行替换。

### 8.2 共享语言包三重校验

配置了 `sharedLocales` 时，初始化会做三重校验：

1. 路径存在
2. 语言文件齐全（源语言 + 所有目标语言的 JSON 都在）
3. key 数量一致（各语言 key 数对齐源语言）

任一不过：交互模式询问是否继续（跳过共享包），非交互模式自动跳过，生成标准 index.ts。**这样共享包有问题时不会悄悄用一半、埋下运行时缺失翻译的坑。**

### 8.3 语言包管理边界

- **新增语言**：每次初始化**完整重建** `index.ts`，不再用「在文件里找位置打补丁」的方式（那种方式文件结构稍有变化就容易静默失败，例如漏注册某语言）。现在配置里有什么语言就注册什么语言。
- **移除语言**：重建时自然不再生成注册，但**不删除**语言包 JSON（防误删）。
- **手动放置但未配置的语言包**：不处理、不提示，以配置为唯一真相来源。
- **僵尸条目**（目标语言有、中文没有）：不处理，以 `zh-CN.json` 为唯一结构基准。

### 8.4 小结：脚本替你挡了什么

| 你可能踩的坑 | 脚本怎么挡 |
| --- | --- |
| 改错位置（同行同中文） | 列号精确定位 + 从后往前 + 长文本优先 |
| 把接口数据误改成 `$t()` | 函数调用 / await 初始化自动跳过 |
| 把提交给后端的值翻译了 | 成员表达式赋值跳过 + 正向匹配 + 预览确认 |
| AI 返回格式错 / 缺条目 | 填空式模板 + 逐条校验 + 3 次重试（缺口补齐） |
| 共享包坏了一半 | 三重校验，不过就跳过 |
| 新增语言漏注册 | 每次完整重建 index.ts |
| 误删语言包 | 移除语言只取消注册、不删文件 |
| 解析失败的文件被静默漏掉 | 明确列出路径和原因 |
| 低质量 key 永久残留 | 无 AI 模式不写 key |
| 重复翻译同一句中文 | 反向映射复用已有 key |
| 非白名单属性遗漏 | `-g` 盲区扫描定位配置遗漏 |
