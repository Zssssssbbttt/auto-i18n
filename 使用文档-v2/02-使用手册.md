# toI18n — Vue 2/3 国际化自动化工具 · 使用手册


## 1. 快速开始

把 `toI18n.cjs` 放到任意目录，直接运行：

```bash
node toI18n.cjs
```

无参数就是**交互模式**：配置 →（可选）AI 翻译 → 预览 → 确认后替换。方向键选、回车确认，随时能停。

- 首次使用走交互模式，跟着向导回答几个关键问题即可。
- 只想看「将要改什么、不动文件」，用 `node toI18n.cjs -d`。

---

## 2. 运行环境

- **Node.js 18 及以上**（脚本依赖 Node 18 内置的网络请求能力，无需装任何额外依赖）。
- 目标项目需为 Vue 2 或 Vue 3 项目（脚本会在初始化时自动安装 `vue-i18n` 依赖）。

---

## 3. 命令行参数

| 参数 | 功能 | 会做什么、产出什么 |
| --- | --- | --- |
| 无参数 | 交互式全流程 | 加载配置 → 初始化 → AI 翻译（可选）→ 预览 → 替换，每一步 Y/n 确认 |
| `-i` / `--init` | 初始化 | 检查/安装 vue-i18n → 生成 `locales` 目录及文件 + 更新 `main.ts` |
| `-t` / `--translate` | AI 翻译 | 扫描中文 → 去重 → 调 AI 翻译 + 补缺口 → 写回语言包。**不碰源码** |
| `-d` / `--dry-run` | 预览 | 只展示将要做的每项改动，不修改任何文件 |
| `-s` / `--scan` | 执行替换 | 改源码（中文 → `$t()`）+ 未匹配提示。**不把未匹配 key 写入语言包** |
| `-g` / `--gap` | 盲区扫描 | 输出所有中文（不受白名单限制），写 `i18n-gap-*.log`，用于定位配置遗漏 |
| `-a` / `--all` | 一键全流程 | init → translate → scan，非交互 |

```bash
node toI18n.cjs -d    # 只看将要改什么，不动文件
node toI18n.cjs -t    # 只执行 AI 翻译
node toI18n.cjs -a    # 一键全流程
```

> **各参数的关系**：`-a` 等价于把 `-i`、`-t`、`-s` 串起来跑；`-d` 是 `-s` 的「只看不改」版本；`-g` 独立于其它模式，用于排查扫描盲区。

---

## 4. 完整运行流程

交互模式分五步（配置 + 初始化 + 可选的 AI 翻译 + 预览 + 替换），**每一步完成后都可以暂停查看结果，再决定是否继续**：

```
第 1 步：配置确认
  → 终端对话式向导，只需回答几个关键问题
  → 其余配置自动写入文件，直接回车保留默认值

第 2 步：初始化
  → 检查/安装 vue-i18n 依赖 → 生成 locales 目录及语言包文件
  → 生成 index.ts、typeToString.ts、toI18n.ts、useI18n.ts
  → 更新 main.ts（补全 i18n 引入、全局 $t 注册、app.use(i18n)；Vue 3 额外注入 @vnet/i18n 公共组件语言包合并）

第 3 步：AI 翻译（可选）
  → 扫描项目中所有中文 → 去重 → 调用 AI 翻译为目标语言
  → 翻译结果展示完毕后暂停，用户可检查翻译质量

第 4 步：预览扫描
  → 逐文件展示将要做的每一项改动（原文本 → 替换结果）
  → 已匹配、未匹配、需人工处理的条目分别归类展示

第 5 步：执行替换
  → 用户最终确认后，执行源码修改 + 语言包更新
  → 自动注入 import 语句
```

**每一步都有 Y/n 确认**，中途 Ctrl+C 安全退出，不产生半成品。

---

## 5. 基础配置入门（必懂三件事）

配置文件 `i18n.config.js` 与脚本放在同一目录。绝大多数场景下，你只需要理解三个配置。

### 5.1 `projectPath` — 目标项目在哪

```js
projectPath: './program/vue3-fundTransfer'
```

**重要：这个路径是相对于脚本 `toI18n.cjs` 所在目录解析的，不是项目自己的目录。** 脚本不知道、也不关心你把它放在哪，一切路径都以脚本所在目录为基准。

### 5.2 `vueVersion` — 项目是 Vue 几

```js
vueVersion: 3   // 或 2
```

决定生成哪套初始化模板、脚本替换成 `$t()` 还是 `this.$t()`、翻译方法默认值。

**如何区分**：看项目 `package.json` 里 `vue` 依赖的版本号（`^2.x` → Vue 2，`^3.x` → Vue 3）。不手动指定时，脚本会自动读取 `package.json` 检测；读不到就默认 Vue 3。

### 5.3 `uiLibrary` — 用的什么组件库

| 值 | 适用场景 |
| --- | --- |
| `element-plus` | Vue 3 PC 端（Element Plus） |
| `vant` | Vue 3 移动端（Vant） |
| `element-ui` | Vue 2（Element UI） |
| `none` | 无组件库 |

它决定生成的语言包初始化模板，以及消息提示方法（`ElMessage` / `Toast` / `this.$message` 等）的默认翻译白名单。**Vue 3 区分移动端/PC 端就看这里：移动端用 `vant`，PC 端用 `element-plus`。** Vue 2 统一用 `element-ui`。

## 6. 完整配置项详解

初始化后自动生成 `i18n.config.js`，含完整默认值。以下逐项说明，标注了默认值，未列出的都用默认即可。

```js
export default {
  // ===== 路径与范围 =====

  // 目标项目根目录（相对脚本所在目录）
  projectPath: '.',

  // 源码根目录（默认 'src'），支持字符串或数组
  // 用于拼接 entry 扫描路径
  baseDir: 'src',
  // baseDir: ['src/views', 'src/components'],   // 数组写法

  // 扫描范围（glob 模式），自动拼接 baseDir
  // entry: ['**/*.vue'] → 实际扫描 src/**/*.vue
  entry: ['**/*.vue'],
  // entry: ['**/*.vue', '**/*.ts'],             // 支持 .vue/.ts/.js 混合

  // 排除文件（glob 模式）
  exclude: [],

  // 语言包输出目录
  output: 'src/locales',

  // ===== 语言 =====

  // 源语言（key 来源），默认中文
  sourceLanguage: 'zh-CN',

  // 目标语言列表（要生成/翻译的语言）
  targetLanguages: ['en'],

  // localStorage 中存储当前语言的 key
  localeStorageKey: 'lang',

  // ===== Vue 版本与组件库 =====

  vueVersion: 3,              // 2 或 3；默认自动检测，读不到默认 3
  uiLibrary: 'element-plus',  // element-plus / vant / element-ui / none

  // ===== 扫描开关 =====

  // 是否扫描 <script> 中的中文（总开关）
  scanScript: true,

  // script 翻译目标变量（正向匹配，精确指定 变量名 → 属性名数组）
  scriptTargets: {},
  // 例：scriptTargets: { columns: ['label', 'title'], options: [] }

  // 是否对纯文本值 const 声明用 computed(() => ...) 包裹（默认 false）
  scriptReactive: false,

  // ===== 白名单 / 黑名单 =====

  // 需要翻译的 HTML 属性（白名单）
  translateAttributes: [
    'label', 'placeholder', 'title', 'title-info', 'alt',
    'message', 'content', 'desc', 'text', 'header', 'menuTitle',
    'start-placeholder', 'end-placeholder', 'error', 'tip',
  ],

  // 永远不翻译的属性（黑名单，优先级高于白名单）
  ignoreAttributes: [
    'style', 'class', 'ref', 'rules', 'model', 'prop',
    'key', 'slot', 'name', 'id', 'type', 'format',
    'value-format', 'range-separator', 'prefix-icon', 'suffix-icon',
    'scoped', 'lang', 'src', 'href', 'target', 'width', 'size',
    'mode', 'disabled', 'clearable', 'filterable', 'remote',
    'reserve-keyword', 'multiple', 'show-overflow-tooltip',
    'align', 'maxlength', 'rows', 'trigger', 'icon',
  ],

  // 需要翻译的方法调用（白名单，支持通配符）
  // 默认值按 vueVersion + uiLibrary 自动设置，此处可手动覆盖
  translateMethods: [
    'ElMessage.*', 'ElMessageBox.*', 'ElNotification.*', 'alert', 'confirm', 'showWarningMessage',
  ],

  // ===== 共享语言包 =====

  // 共享语言包路径列表（相对 projectPath）
  sharedLocales: [],

  // ===== 日志 =====

  logDir: 'logs',

  // ===== AI 翻译 =====
  ai: {
    enabled: true,

    // 参考语言包路径，翻译时优先复用已有翻译
    referenceLocales: [],

    // OpenAI 兼容 API 配置
    apiKey: 'sk-xxx',
    baseURL: 'https://api.openai.com/v1',
    model: 'gpt-4o',
    temperature: 0.3,
    maxTokens: 200000,

    // 每批最多翻译条数
    batchSize: 200,
  },
}
```

### 关键配置项补充说明

- **`scriptTargets`**：脚本翻译的核心。`{ columns: ['label', 'title'] }` 只翻译 `columns` 变量的 `label`、`title` 属性；值为 `[]` 表示翻译该变量内所有中文（递归）。**不在配置中的变量不会被翻译**（宁可漏，也不瞎改）。详见《01-项目说明》4.2。
- **`sharedLocales`**：多个项目共用一套公共语言包时使用。初始化时深度合并，项目自身翻译覆盖共享包。校验规则见《01-项目说明》6.3。
- **`ai.referenceLocales`**：翻译时优先复用已有语言包里的 key 映射，避免重复翻译、保证跨项目 key 一致。
- **`entry` / `baseDir`**：`baseDir` 与 `entry` 自动拼接生成实际扫描路径；`entry` 已包含 baseDir 前缀或以 `./`、`../` 开头时不会重复拼接。

## 8. typeToString 与 toI18n 是什么、怎么用

初始化时会在 `locales/` 下生成两个辅助文件，解决**静态扫描替换解决不了**的运行时翻译问题。

### 8.1 `i18nTypeToString` — 解决 TS 类型报错

`$t()` 返回值在 TS 里是联合类型，赋给要求 `string` 类型的属性/参数时会编译报错。用 `i18nTypeToString` 强制转成 `string`：

```ts
// 直接使用 $t，TS 可能报错（联合类型不兼容 string）
const config = { title: $t('common.title') }

// 改用 i18nTypeToString，返回类型明确为 string
const config = { title: i18nTypeToString('common.title') }
```

```vue
<!-- 模板中同样可用（已全局注册，无需 import） -->
<el-table-column :label="i18nTypeToString('common.applicant')" />
```

### 8.2 `translateText` / `translateArray` — 翻译接口返回的中文

接口返回的中文数据（状态名、下拉选项、审批节点等）编译期看不到，无法用静态替换。这两个方法在**运行时**通过「中文 → key」反向映射查到翻译。

**`translateText` 单条翻译**：

```vue
<!-- 模板：下拉选项的 label 来自接口返回的中文 -->
<el-option
  v-for="item in options"
  :key="item.id"
  :label="translateText(item.name)"
  :value="item.id"
/>
```

```js
// Vue 3：从 toI18n 导入后直接调用
import { translateText } from '@/locales/toI18n'
const displayName = translateText(approverName)

// Vue 2：已注册到原型，通过 this 访问
const displayName = this.translateText(this.approverName)
```

**`translateArray` 批量翻译数组**（返回新数组，原数组不变）：

```js
import { translateArray } from '@/locales/toI18n'

// 接口返回: [{ id: 1, name: '待审核' }, { id: 2, name: '已通过' }]
this.viewBtns = translateArray(res.data, 'name')
// 英文环境 → [{ id: 1, name: 'Pending' }, { id: 2, name: 'Approved' }]
```

典型使用位置：接口响应处理处（如 `getList().then(res => this.viewBtns = translateArray(res.data, 'name'))`），一次转换，模板直接渲染翻译后的数据。

### 8.3 前提与分工

| 场景 | 处理方式 |
| --- | --- |
| 源码中硬编码的中文 | `-s` 编译期替换为 `$t('key')` |
| 接口返回的中文（状态、选项等） | 运行时 `translateText` / `translateArray` |
| 语言包中不存在的中文 | 先 `-t`（AI 生成 key + 翻译）或手动补充，两种方法才生效 |

### 8.4 `useI18n` — 在 script setup 中获取 t 函数

初始化时生成的 `useI18n.ts` 提供了一个 composable，在 `<script setup>` 中手动调用 `$t`：

```js
import { useI18n } from '@/locales/useI18n'
const { t } = useI18n()
const label = t('common.submit')
```

模板中已有全局 `$t`，通常不需要手动调用，此 composable 仅用于脚本中需要 `t()` 的场景。

### 8.5 Vue 2：`switchLanguage` 手动切换语言

Vue 2 项目生成的 `index.ts` 额外导出 `switchLanguage(lang)` 方法，用于同时切换 vue-i18n 和 Element UI 的语言：

```js
import { switchLanguage } from '@/locales'
switchLanguage('en')
```

Vue 3 项目语言切换由 `index.ts` 内部的 watch 自动同步，无需手动调用。

> **注意**：接口数据要能翻译，前提是该中文**已存在于 `zh-CN.json`** 中。反向映射在应用启动时构建一次，之后新增的词条重启应用后生效。

## 9. 新增语言 / 移除语言

### 9.1 新增语言（两步）

```
1. 在 i18n.config.js 的 targetLanguages 中加语言代码，如 ['en', 'th']
2. 重新执行 node toI18n.cjs
```

工具自动检测已有中文翻译中哪些语言缺失，调用 AI 一次性补齐，**已有翻译完全不受影响**。同时初始化会完整重建 `index.ts`，新语言的 import、messages 条目、组件库 locale 注册全部自动生成。

实际运行效果（新增泰语为例）：

```
[2/4] 加载已有翻译...
  本项目语言包: 96 条
  翻译缺口: 96 条

[3b/4] 补齐翻译缺口...
  缺口组 [th]: 96 条，分 1 批
    ✓ 完成

AI 翻译完成
  新增翻译:     0
  缺口补齐:     96
  失败批次:     0
```

三个语言包（zh-CN / en / th）各 96 条，结构完全一致，原有 en.json 零修改。

### 9.2 移除语言

```
1. 在 i18n.config.js 的 targetLanguages 中删掉语言代码
2. 重新执行 node toI18n.cjs
```

重建 `index.ts` 时自然不再生成该语言的注册。**语言包 JSON 文件不会被删除**（防止误删），如需彻底清理请手动删除对应文件。

## 10. 注意事项

1. **先 dry-run**：执行 `-d` 预览所有改动，确认无误后再 `-s` 执行替换
2. **`$t` 全局可用**：初始化时已全局注册 `$t`，模板和脚本中直接使用，无需 import
3. **语言切换**：使用 vue-i18n 的 `locale` 响应式切换，无需手动刷新页面
4. **日志**：每次扫描会在 `logs/` 目录生成日志文件，记录所有改动
5. **Key 复用**：同一中文始终映射到同一 key，不会重复翻译
