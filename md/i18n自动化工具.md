> 上半：项目说明｜下半：使用手册

# 第一部分：项目说明

## 1. 这是什么

做 Vue 3 国际化，麻烦的不是接 vue-i18n，是把页面里成片的中文改成 `$t('key')`，再把语言包对齐。

这个工具把扫描、翻译、预览、替换串成一条流水线。交付物是一个文件：`toI18n.cjs`，放到任意目录直接跑，只需配置目标项目路径即可。

## 2. 为什么要做

### 2.1 实际问题

| 痛点                     | 真实情况                         |
| ------------------------ | -------------------------------- |
| 接 vue-i18n              | 很快                             |
| 硬编码中文改成 `$t()`    | 页面一多就容易漏，也费时间       |
| 同一句中文对应同一个 key | 人工很难保持一致                 |
| 再加一门语言             | 容易动到已有翻译，又得整包过一遍 |

框架接入不难，对于存量改造和一致性有些困难。

### 2.2 为什么不用正则硬扫

正则只能找到"这行有中文"，分不清：

- 用户能看见的文案，还是 class、注释、业务数据
- 是不是已经包在 `$t()` 里了
- 动态绑定、三元、方法参数该怎么改才安全

改错就直接炸页面。所以用 AST（Vue 模板编译器 + Babel）定位，不靠猜。

### 2.3 落地原则

全自动一键改完不现实，风险太大。做法是：

1. 白名单里的展示文案：自动换
2. 拿不准的：标出来，人来看
3. 真正改文件前：必须先预览确认

**宁可漏，也不瞎改。**

## 4. Template 与 Script 分别处理

### 4.1 Template 解析（`<template>` 部分）

模板解析使用 Vue 官方编译器 `@vue/compiler-dom` 将模板解析为 AST，然后按节点类型分类处理。所有处理受 `i18n.config.js` 中的白名单/黑名单控制。

**会自动替换的情况：**

| 类型       | 原始写法                                            | 替换后                                                                     | 触发条件                                                              |
| ---------- | --------------------------------------------------- | -------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 静态属性   | `<el-input label="申请人" />`                       | `<el-input :label="$t('common.applicant')" />`                             | 属性名在 `translateAttributes` 白名单且不在 `ignoreAttributes` 黑名单 |
| 动态属性   | `:placeholder="status === 1 ? '已通过' : '待审核'"` | `:placeholder="status === 1 ? $t('common.passed') : $t('common.pending')"` | `:attr` 或 `v-bind:attr`，属性名在白名单，表达式内含中文字符串        |
| 文本内容   | `<el-button>确认删除</el-button>`                   | `<el-button>{{ $t('common.confirmDelete') }}</el-button>`                  | 标签间的纯文本节点，包含中文                                          |
| 插值表达式 | `{{ status === 1 ? '启用' : '禁用' }}`              | `{{ status === 1 ? $t('common.enable') : $t('common.disable') }}`          | `{{ }}` 内含中文字符串                                                |

**会自动跳过的情况：**

| 原始写法                         | 跳过原因                                                                                                 |
| -------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `<div class="中文类名">`         | `class` 在 `ignoreAttributes` 黑名单                                                                     |
| `v-if="status === '已通过'"`     | `v-if` 指令名不是 `bind`，无法确定属性名                                                                 |
| `@click="handle('确认')"`        | 事件绑定，不在白名单                                                                                     |
| `{{ $t('already.translated') }}` | 已被 `$t()` 包裹，避免二次替换                                                                           |
| `<el-radio label="已通过">`      | `label` 在白名单但组件不同含义不同（radio 的 label 是后端数据值），后续将通过 `组件.属性` 级精确配置优化 |

**会被标记为"特殊-未处理"的情况：**

| 类型             | 示例                    | 原因                                   |
| ---------------- | ----------------------- | -------------------------------------- |
| 不在白名单的属性 | `empty-text="暂无数据"` | 自定义组件属性，可能也需要翻译但需确认 |

### 4.2 Script 解析（`<script>` / `<script setup>` 部分）

脚本解析使用 `@babel/parser` + `@babel/traverse` 解析 JS/TS 为 AST，支持 `.vue` 文件中的 `<script>` 块以及独立的 `.ts` / `.js` 文件。

配置项 `scanScript` 控制是否扫描脚本中的中文（总开关）。

脚本解析通过两种机制覆盖不同的中文使用场景，两者**并行生效、互不冲突**：

- **`scriptTargets`** — 处理变量声明中的展示文案（如表格列定义、表单配置等对象属性）
- **`translateMethods`** — 处理方法调用中的提示文案（如 ElMessage、确认框等用户可见消息）

一个文件中可以同时使用两种机制，各自独立工作。关闭 `scanScript` 总开关后两者均不生效。

#### 机制一：变量声明正向匹配（`scriptTargets`）

用户精确指定要翻译的**变量名 → 属性名数组**，如：

```js
scriptTargets: {
  columns: ['label', 'title'],   // 只翻译 columns 中 label 和 title 属性
  rules: ['message'],             // 只翻译 rules 中 message 属性
  options: [],                    // [] 表示翻译该变量内所有中文（全量翻译）
}
```

**不在配置中的变量不会被翻译。** 这避免了"一刀切"导致的误替换。

| 场景           | 原始写法                             | 替换后                                                |
| -------------- | ------------------------------------ | ----------------------------------------------------- |
| 对象属性       | `{ label: '请输入名称' }`            | `{ label: $t('common.pleaseEnterName') }`             |
| 三元表达式     | `{ label: cond ? '是' : '否' }`      | `{ label: cond ? $t('k1') : $t('k2') }`               |
| 模板插值       | `` `共${n}条记录` ``                 | `` `${$t('k1')}${n}${$t('k2')}` ``                    |
| 字符串拼接     | `'共' + n + '条'`                    | `$t('k1') + n + $t('k2')`                              |
| 数组嵌套       | `[{ label: '中文' }]`                | 递归处理每个元素                                      |
| 深层嵌套       | `{ children: { label: '中文' } }`    | 递归进入嵌套对象                                      |

**接口数据自动跳过：** 当变量初始化是函数调用（非 ref/reactive）或 await 表达式时，认为数据来自接口返回，自动跳过不翻译。例如：

```js
const data = fetchData()                // 跳过 — 接口数据
const list = await getList()            // 跳过 — 接口数据
const form = ref({ label: '中文' })     // 处理 — Vue 响应式声明
const columns = [{ label: '中文' }]     // 处理 — 静态声明
```

这些判断体现了脚本解析的**上下文感知**能力——不仅检测字符串是否包含中文，还会结合变量声明方式（静态声明、接口数据、响应式包裹）来决策是否翻译，避免误改接口返回的动态数据。

**响应式包裹（`scriptReactive`）：** 当 `scriptReactive: true` 时，对纯文本值 `const` 声明的翻译目标变量自动包裹 `computed(() => ...)`，使翻译结果随语言切换响应式更新。`let` 变量不包裹。`ref()`/`reactive()` 包裹的变量不处理（本身已具备响应式，包裹会破坏类型）。

```js
// 替换前
export const columns = [{ label: '姓名' }]
export const title = '页面标题'

// 替换后（scriptReactive: true）
import { computed } from 'vue'
export const columns = computed(() => [{ label: $t('common.name') }])
export const title = computed(() => $t('common.page_title'))

// 替换后（scriptReactive: false，默认）
export const columns = [{ label: $t('common.name') }]
export const title = $t('common.page_title')
```

#### 机制二：方法调用白名单（`translateMethods`）

白名单内的函数调用参数中的中文自动翻译，支持通配符。

```js
translateMethods: [
  'ElMessage.*',         // 通配符：匹配 ElMessage.success / .warning / .error 等
  'ElMessageBox.*',      // 通配符：匹配 ElMessageBox.confirm / .alert 等
  'ElNotification.*',    // 通配符：匹配 ElNotification 所有子方法
  'alert',               // 精确匹配：全局 alert()
  'confirm',             // 精确匹配：全局 confirm()
]
```

| 类型           | 原始写法                             | 替换后                                                |
| -------------- | ------------------------------------ | ----------------------------------------------------- |
| 白名单方法调用 | `ElMessage.warning('请先选择数据')`  | `ElMessage.warning($t('common.pleaseSelectData'))`    |
| 白名单方法调用 | `ElMessageBox.confirm('确认删除？')` | `ElMessageBox.confirm($t('common.confirmDeleteQ'))`   |
| 通配符匹配     | `ElMessage.success('操作成功')`      | `ElMessage.success($t('common.operationSuccess'))`    |

`ElMessage.*` 一条通配规则即可覆盖该对象下所有方法调用。默认值根据 `uiLibrary` 自动设置：Element Plus → `ElMessage.*` 等，Vant → `Toast.*`，无组件库 → 空。

**会自动跳过的情况：**

| 原始写法                    | 跳过原因                                     |
| --------------------------- | -------------------------------------------- |
| `form.status = '已通过'`    | 成员表达式赋值，自动识别为数据值而非展示文本 |
| `import { ref } from 'vue'` | import 声明                                  |
| `type Status = '已通过'`    | TS 类型注解                                  |
| 不在白名单的方法参数        | `console.log('调试信息')`                    |
| 变量名不在 `scriptTargets` 中 | 正向匹配——未配置的变量不翻译              |

**会被标记为"特殊-未处理"的情况：**

| 类型             | 示例                  | 原因                   |
| ---------------- | --------------------- | ---------------------- |
| 模板字符串含变量 | `共${total}条记录`    | 变量参数需人工设计     |
| 字符串拼接       | `'完成时间：' + date` | 拼接语序问题需人工处理 |
| 字符串含 HTML 标签 | `'当<b>不是</b>时'` | 避免 AI 翻译破坏 HTML 标签结构 |

## 5. 特殊处理与安全机制

### 5.1 自动标记"需要人工处理"的边界情况

工具会将无法安全自动处理的条目单独归类为"特殊-未处理"，标注位置、类型、原因，不自动替换，交由人工逐条确认。

此外，**含 HTML 标签的字符串**（如 `<b>重要</b>提示`）也会被自动检测并标记为特殊项，避免 AI 翻译时破坏标签结构。这类条目会写入 `logs/i18n-special-<时间戳>.log` 日志文件。

### 5.2 翻译阶段也有分类记录

对于符合白名单配置但被特定规则过滤掉的文本（如注释中的中文、`$t()` 已有的调用、纯数字/符号等），AI 翻译阶段同样会分类记录到日志，方便人工复核是否有遗漏。

### 5.3 安全替换策略

- **从后往前按行替换**：先改后面行，前面行号不受影响
- **同行长文本优先**：避免短文本先匹配导致长文本错位
- **自动注入 import**：检测文件是否用了 `$t()` 但缺少 import，自动补全 `import { $t } from '@/locales'`；若使用了 `computed` 也会自动补全对应的 vue import

## 6. 关键技术点

### 6.1 AI 翻译：填空式 JSON + 缺口补齐

**新文本翻译：** AI 为每条中文生成 `module.keyName` 和目标语言翻译。

**新增语言补齐：** 当项目已有 100+ 条双语翻译后想加第三种语言，工具自动检测"已有 key 但目标语言缺失"的缺口，按缺失语言组合分组，用带空位的 JSON 模板让 AI 填空：

```json
// 输入（模板）
{"transfer.sponsor": {"th": ""}, "transfer.status": {"th": ""}}
// 输出（AI 填空）
{"transfer.sponsor": {"th": "ผู้สนับสนุน"}, "transfer.status": {"th": "สถานะการโอน"}}
```

AI 只需填空，无需自组织 JSON，大幅降低格式错误概率。返回结果逐条校验，缺失项自动重试（最多 3 次），失败的记入日志。

### 6.2 Key 生成：复用已有翻译

```
内置常用词汇映射（100+ 条，如 发起人→sponsor）
  > 已有语言包反向映射（中文→已有 Key）
  > AI 生成（根据语义自动生成 module.keyName）
```

同一中文始终映射到同一 key，不会出现重复翻译或不一致。

### 6.3 外部共享语言包（`sharedLocales`）

如果项目使用了多个仓库共享的公共语言包，可以通过 `sharedLocales` 配置引入。初始化时会校验共享包的完整性，校验通过的共享包会被深度合并到 i18n 实例中——项目自身的翻译优先级高于共享包（项目覆盖共享）。

**共享包校验规则（三条，必须全部通过）：**

1. **路径存在** — 配置的目录路径必须存在
2. **语言文件齐全** — 必须包含源语言和所有目标语言的 `.json` 文件
3. **Key 数量一致** — 各语言文件的 key 数量必须与源语言一致

校验不通过时，交互模式会询问是否继续（跳过共享包），非交互模式自动跳过，生成标准 index.ts。

## 7. 组件库兼容

### 7.1 UI 组件库国际化一致性

工具根据 `uiLibrary` 配置自动适配不同 UI 库。PC 端和移动端的主要区别在于使用的 UI 组件库不同：PC 端通常使用 Element Plus，移动端通常使用 Vant。工具据此生成对应的 i18n 配置模板，并自动设置相应的翻译方法白名单。

| uiLibrary | 说明 | 自动设置 |
|-----------|------|---------|
| `element-plus` | PC 端常用 | 生成 Element Plus locale 集成代码，translateMethods 默认 `ElMessage.*` 等 |
| `vant` | 移动端常用 | 生成精简模板，translateMethods 默认 `Toast.*` |
| `none` | 无组件库 | 仅 vue-i18n 核心配置，translateMethods 默认空 |

Element Plus 集成做了两件事确保组件库语言与项目语言始终保持一致：
- **watch 同步**：监听 i18n locale 变化，自动切换 Element Plus 语言包
- **install 拦截**：在 `app.use(i18n)` 时自动 provide Element Plus 的 locale

### 7.2 `@vnet/i18n` 公共组件库兼容

初始化时会自动往 `main.ts` 注入 `@vnet/i18n` 的相关代码：

```ts
import { setI18nInstance, getComponentMessages } from '@vnet/i18n'

// 将公共组件词条合并到当前 i18n 实例
const compMsgs = getComponentMessages()
for (const locale of Object.keys(compMsgs)) {
  i18n.global.mergeLocaleMessage(locale, compMsgs[locale])
}
// 注册到 @vnet/i18n，使 FlowProcess 等公共组件能随项目语言切换
setI18nInstance(i18n)
```

这样公共组件（如审批流程、文件上传等）的语言会跟随项目语言自动切换。

# 第二部分：使用手册

## A. 怎么跑

```bash
node toI18n.cjs
```

无参数就是交互模式：配置 →（可选）翻译 → 预览 → 确认后替换。方向键选，回车确认，随时能停。

## 1. 执行流程

工具分四步执行，**每一步完成后都可以暂停查看结果，再决定是否继续**：

```
第 1 步：配置确认
  → 终端对话式向导，只需回答几个关键问题
  → 其余配置自动写入文件，直接回车保留默认值

第 2 步：AI 翻译（可选）
  → 扫描项目中所有中文 → 去重 → 调用 AI 翻译为目标语言
  → 翻译结果展示完毕后暂停，用户可检查翻译质量

第 3 步：预览扫描
  → 逐文件展示将要做的每一项改动（原文本 → 替换结果）
  → 已匹配、未匹配、需人工处理的条目分别归类展示

第 4 步：执行替换
  → 用户最终确认后，执行源码修改 + 语言包更新
  → 自动注入 import 语句
```

**每一步都有 Y/n 确认**，中途 Ctrl+C 安全退出，不产生半成品。

### 2 隐藏命令（进阶使用）

支持通过命令行参数直接跳到特定步骤，适合 CI/CD 或重复执行：

| 参数                 | 功能                                       |
| -------------------- | ------------------------------------------ |
| `-i` / `--init`      | 初始化 locales 目录结构和配置文件          |
| `-t` / `--translate` | AI 翻译（扫描 → 去重 → 翻译 → 写回语言包） |
| `-d` / `--dry-run`   | 预览模式，只展示改动明细，不修改文件       |
| `-s` / `--scan`      | 执行替换（修改源文件 + 更新语言包）        |
| `-g` / `--gap`       | 盲区扫描（列出所有中文，定位配置遗漏）     |
| `-a` / `--all`       | 全流程一键执行（init → translate → scan）  |

```bash
node toI18n.cjs -d    # 只看将要改什么，不动文件
node toI18n.cjs -t    # 只执行 AI 翻译
node toI18n.cjs -a    # 一键全流程
```

## 3. 配置设计

### 3.1 对话式配置只需回答几个关键问题

| 步骤 | 问题                       | 说明                                                     |
| ---- | -------------------------- | -------------------------------------------------------- |
| 1    | 项目根目录                 | 需要国际化的项目路径                                   |
| 2    | 源码语言 / 目标语言        | 目标语言多选（en、th、ja、ko 等）                        |
| 3    | 是否启用 AI 翻译           | 启用后补充 API Key（脱敏输入）、地址、模型名称（预设可选）|
| 4    | 是否扫描 script 中的中文   | 总开关，关闭则只处理模板                                 |
| 5    | Script 翻译目标变量        | 精确配置哪些变量的哪些属性需要翻译，附带格式示例         |
| 6    | 是否用 computed 包裹       | const 声明变量包裹后翻译结果响应式更新                    |
| 7    | UI 组件库                  | 选择 Element Plus / Vant / 无，决定模板和翻译方法默认值   |

**AI 模型选择**：提供 gpt-4o、gpt-4、deepseek-v4-pro、deepseek-chat、claude-sonnet-4-6 等预设，方向键选择；也可选「自定义」手动输入任意模型名。

**其余所有配置**（属性白名单、黑名单、方法白名单、排除文件、Key 风格、日志目录、共享语言包等）在初始化时自动写入 `i18n.config.js`，脚本运行时正常读取，无需在对话中逐项确认。

### 3.2 配置文件的角色

- **初始化时**：自动生成包含完整默认值的配置文件
- **运行时**：脚本读取 `i18n.config.js` 中的每一项来控制扫描、过滤、替换行为
- **需要微调时**：直接编辑配置文件，无需重跑配置向导

这样设计的原因：属性白名单/黑名单等配置项数量多、通用性强、大多数项目不需要改，放对话式配置里逐项问反而增加负担。放入配置文件，既保证运行时完整读取，又让对话式配置保持简洁。

### 3.3 交互细节

- 方向键 `↑↓` 导航选择，Enter 确认
- API Key 脱敏（输入时显示 `*`，已有值显示 `sk-Ix****RI8C`）
- 确认完毕一次性写入，Ctrl+C 退出不产生半成品

## 4. Script 标签配置详解

### 4.1 `scriptTargets` — 翻译目标变量

精确指定需要翻译的变量名及其属性，采用**正向匹配**模式——只有在配置中声明的变量才会被翻译。

```js
// i18n.config.js
scriptTargets: {
  columns: ['label', 'title'],   // 只翻译 columns 中 label、title 属性
  rules: ['message'],             // 只翻译 rules 中 message 属性
  options: [],                    // [] = 翻译该变量内所有中文
}
```

**对话式配置中的输入格式**（空格分隔多个变量，冒号后跟属性列表）：

```
columns:label,title  rules:message  options
```

规则：
- **不在配置中的变量不会被翻译**（宁可漏，也不瞎改）
- 属性数组为空 `[]` 表示全量翻译该变量内所有中文（递归遍历对象/数组/三元表达式等）
- 支持深层嵌套：`{ children: { label: '中文' } }` 会被递归处理
- 支持数组嵌套：`[{ label: '中文' }, { label: '中文2' }]` 每个元素都会被处理
- **接口数据自动跳过**：变量 init 为函数调用（非 ref/reactive）或 await 时，认为数据来自接口，不翻译
- `ref()` 和 `reactive()` 包裹的值会自动展开后处理

### 4.2 `scriptReactive` — 响应式包裹

控制是否对纯文本值 `const` 声明的翻译目标用 `computed(() => ...)` 包裹。默认 `false`。

```js
scriptReactive: true   // 纯文本值 const 变量包裹 computed，切换语言时自动更新
scriptReactive: false  // 默认，直接替换为 $t('key')，不做包裹
```

规则：
- 仅对 `const` 声明的变量生效，`let`/`var` 永不包裹
- 仅当 init 为纯字符串/模板字符串时生效（如 `const title = '中文'`）
- `ref()`/`reactive()` 包裹的变量不处理，避免破坏类型
- 包裹时自动注入 `import { computed } from 'vue'`
- 仅对 `scriptTargets` 中配置的变量生效

### 4.3 `translateMethods` — 方法调用白名单

指定哪些函数调用的参数需要翻译，支持精确匹配和通配符。

```js
// i18n.config.js
translateMethods: [
  'ElMessage.*',         // 通配符：匹配 ElMessage.success / .warning / .error 等
  'ElMessageBox.*',      // 通配符：匹配 ElMessageBox.confirm / .alert 等
  'ElNotification.*',    // 通配符：匹配 ElNotification 所有子方法
  'alert',               // 精确匹配：全局 alert('提示')
  'confirm',             // 精确匹配：全局 confirm('确认删除？')
]
```

规则：
- 支持 `*` 通配符：`ElMessage.*` 一条规则覆盖该对象下所有方法
- 不在白名单中的方法调用参数不会翻译（如 `console.log('调试')` 会被跳过）
- 默认值根据 `uiLibrary` 自动设置：Element Plus → `ElMessage.*` 等，Vant → `Toast.*`，无组件库 → 空

## 5. 外部共享语言包

### 5.1 使用场景

当多个项目共用一套公共组件的翻译时，可将公共语言包作为共享包引入，避免每个项目重复维护相同翻译。

### 5.2 配置方式

```js
// i18n.config.js
sharedLocales: ['../common-ui/src/locales']
```

### 5.3 合并策略

初始化时生成的 `index.ts` 会使用深度合并：共享语言包在前，项目语言包覆盖在后。这意味着项目可以对共享包中的任意 key 进行覆盖，而无需修改共享包。

### 5.4 校验规则

共享包必须同时满足以下三条规则，否则跳过不使用（交互模式下允许用户选择是否继续）：

1. **路径存在** — 配置的目录路径必须存在
2. **语言文件齐全** — 必须包含源语言和全部目标语言的 `.json` 文件（如 `zh-CN.json`、`en.json`、`th.json`）
3. **Key 数量一致** — 各语言文件的 key 数量必须与源语言一致，确保翻译完整

## 6. 新增语言只需两步

```
1. 在 i18n.config.js 的 targetLanguages 中加一个语言代码，如 ['en', 'th']
2. 重新执行 node toI18n.cjs
```

工具自动检测已有中文翻译中哪些语言缺失，调用 AI 一次性补齐，**已有翻译完全不受影响**。

三个语言包（zh-CN / en / th）各 96 条，结构完全一致，原有 en.json 零修改。

# 第三部分：持续优化中

Script 标签国际化当前采用"正向匹配"模式，需要用户手动配置变量名和属性名。后续计划扩展以下能力：

- **反向查找**：不限定变量名，全局扫描所有对象，自动发现需翻译的展示文案
- **通配符变量名匹配**：支持 `*_MAP`、`*_LIST` 等模式，批量匹配同类变量
- **跨文件 import 追踪**：识别从其他文件 import 进来的常量对象，追溯翻译
- **枚举对象全量翻译**：自动识别 `STATUS_MAP`、`LABEL_MAP` 等枚举模式，翻译所有 value
