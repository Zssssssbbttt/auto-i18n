## 二、CLI 入口 — `index.cjs`

### 运行模式

| 命令 | 模式 | 功能 |
|------|------|------|
| 无参数 | interactive | 交互式全流程：配置向导 → 初始化 → AI翻译(可选) → 预览 → 替换 |
| `-i` / `--init` | init | 仅初始化 locales 目录结构 |
| `-t` / `--translate` | translate | 仅 AI 翻译（扫描 → 去重 → 调 API → 写回） |
| `-s` / `--scan` | scan | 仅扫描替换 |
| `-d` / `--dry-run` | dry | 预览模式，只输出不修改 |
| `-g` / `--gap` | gap | 盲区扫描，输出所有中文（不受白名单限制） |
| `-a` / `--all` | all | 全流程：init → translate → scan |

### 核心函数

#### `detectVueVersion(config)` — Vue 版本检测

优先级：**配置显式指定 > package.json 自动检测 > 默认 3**

```js
// 1. 配置文件显式指定 → 优先
if (config.vueVersion) return config.vueVersion
// 2. package.json 中 vue 依赖版本号（^2 → 2, ^3 → 3）
// 3. 默认 Vue 3
```

#### `normalizeConfig(config)` — 配置规范化

填充所有默认值，包含两个重要逻辑：

**baseDir 解析**（支持字符串/数组，自动拼接 entry）：
```js
// baseDir: "src", entry: ["**/*.vue"] → entry: ["src/**/*.vue"]
// baseDir: ["src/views", "src/components"], entry: ["**/*.vue"]
//   → entry: ["src/views/**/*.vue", "src/components/**/*.vue"]
// entry 已含 baseDir 前缀或以 ./ ../ 开头 → 不重复拼接
```

**translateMethods 默认值**（按 Vue 版本 + UI 库）：
```js
getDefaultTranslateMethods(vueVersion, uiLibrary)
// Vue 2 → ['this.$message.*', 'this.$confirm', ...]（不区分 UI 库）
// Vue 3 + element-plus → ['ElMessage.*', 'ElMessageBox.*', ...]
// Vue 3 + vant → ['Toast', 'Toast.*']
// Vue 3 + none → []
```

#### `ensureVueI18n(projectRoot, vueVersion)` — 依赖自动安装

检查 `package.json` 中是否有 `vue-i18n` 依赖，缺失则自动安装：
- Vue 2 → `vue-i18n@8`
- Vue 3 → `vue-i18n`（v9+）
- 自动识别包管理器：`pnpm-lock.yaml` → pnpm，`yarn.lock` → yarn，否则 npm

#### `prepareScanResults(config, projectRoot)` — 扫描分类核心

dry-run / scan / gap 三个模式共用此函数：
1. 加载 locale 反向映射
2. 调用 `scanFiles` 扫描全部文件
3. 遍历结果分类：
   - 特殊类型（模板插值/字符串拼接/含 HTML 标签）→ `special` 数组
   - 反向映射查得到 key → `matched` 数组
   - 查不到 → `unmatched` 数组
4. 去重（同一文件同一行同一中文只保留一条）

## 三、初始化模块 — `init.cjs` + `init/`

### 模块结构

```
init.cjs          # 共享逻辑：目录创建、语言包空文件、共享包校验、版本调度
init/
  init-vue2.cjs   # Vue 2 专用：生成模板、更新 main.ts
  init-vue3.cjs   # Vue 3 专用：生成模板、更新 main.ts
```

`init.cjs` 通过 `require('./init/init-vue${vueVersion}.cjs')` 动态加载对应版本模块。

### `runInit(config, projectRoot, options)` 流程

```
1. 创建输出目录（src/locales）
2. 创建语言包空文件（zh-CN.json / en.json 等，已存在跳过）
3. 校验 sharedLocales（路径存在、文件齐全、key 数量一致）
4. 完整重建 index.ts（每次遍历所有配置语言重新生成）
5. 创建 typeToString.ts / toI18n.ts / useI18n.ts（已存在跳过）
6. 更新 main.ts
```

### `generateIndexContent` — index.ts 模板生成

**Vue 2 + Element UI** 模板要点：
```ts
import Vue from 'vue'
import VueI18n from 'vue-i18n'
import zhCN from './zh-CN.json'
import elementZhCN from 'element-ui/lib/locale/lang/zh-CN'
// ... 所有配置语言动态生成

Vue.use(VueI18n)
const i18n = new VueI18n({ locale, messages })
elementLocale.use(elementLocales[i18n.locale])
export const $t = i18n.t.bind(i18n)
export function switchLanguage(lang) { ... }
```

**Vue 3 + Element Plus** 模板要点：
```ts
import { createI18n } from 'vue-i18n'
import zhCNElement from 'element-plus/dist/locale/zh-cn.mjs'
// ... 所有配置语言动态生成（与 Vue 2 一致）

const i18n = createI18n({ legacy: false, locale, messages })
// watch 监听 locale 变化同步 Element Plus 语言
// 拦截 install 在 app.use(i18n) 时 provide localeContextKey
export const $t = i18n.global.t
export function setupI18n(app) { ... }
```

**精简模板**（vant / none）：仅 vue-i18n 核心配置，无 UI 库耦合。

**共享语言包**（sharedLocales 配置）：生成 `deepMerge` 工具函数，messages 使用深度合并，共享包在前、项目包在后（项目覆盖共享）。

### `updateMainTs` — main.ts 自动更新

**Vue 3** 注入 4 类代码：
1. `import i18n, { $t } from './locales'`
2. `import { setI18nInstance, getComponentMessages } from '@vnet/i18n'`
3. `app.config.globalProperties.$t = $t` + @vnet/i18n 注册（合并公共组件词条）
4. `app.use(i18n)`（在 `.mount(` 前插入，支持 3 种链式调用写法）

**Vue 2** 注入 3 类代码（无 @vnet/i18n，Vue 2 无公共组件）：
1. `import i18n, { $t } from './locales'`
2. `Vue.prototype.$t = $t`
3. `new Vue({ i18n, ... })` 选项注入

## 五、解析器 — `parsers/`

### 5.1 `vue-sfc-parser.cjs` — SFC 文件解析

**技术**：`@vue/compiler-sfc` 的 `parse()` 函数

```js
sfc = parseSFC(source, { filename: filePath })
// sfc.descriptor.template     → <template> 内容
// sfc.descriptor.script       → <script> 内容
// sfc.descriptor.scriptSetup  → <script setup> 内容
```

**行号换算**：`scriptStartLine = scriptBlock.loc.start.line - 1`，因为 template/script 内容是从标签后开始的，解析器拿到的行号是块内相对行号，需要加上块起始行号才能对应到文件真实行号。

**流程**：
```
parseSFC → 检查解析错误
  → template 存在 → parseTemplate（template AST）
  → scanScript 开启 → parseScript × (script + scriptSetup)
  → 结果打上 file 和 section 标记
```

### 5.2 `template-parser.cjs` — 模板 AST 解析

**技术**：`@vue/compiler-dom` 的 `parse()` 函数，产出 Vue 模板 AST

```js
ast = parse(template, { comments: true, getTextMode: () => 0 })
// getTextMode: () => 0 表示按 DATA 模式解析（非 RCDATA/RAWTEXT）
```

**AST 节点类型**（switch 分发）：

| 节点类型 | 处理函数 | 识别目标 |
|----------|----------|----------|
| ELEMENT | `walkElement` | 元素节点 → 检查属性 |
| TEXT | `walkText` | `<span>中文</span>` |
| INTERPOLATION | `walkInterpolation` | `{{ 中文 }}` |
| COMPOUND_EXPRESSION | `walkCompoundExpression` | 复合表达式 |
| COMMENT | — | 跳过注释 |

**属性识别**（`walkElement` 中）：

```
静态属性 ATTRIBUTE: label="中文"
  → handleStaticAttribute
  → 检查: 含中文 → 不在 ignoreAttributes 黑名单 → 在 translateAttributes 白名单
  → 产出 { type: 'static-attr', attrName, col }

指令 DIRECTIVE: :label="..."  /  v-bind:label="..."
  → handleDirective
  → 提取 argName（bind 的参数名）
  → 同样检查黑白名单
  → 表达式含中文 → 产出 { type: 'dynamic-attr' }
  → 表达式含模板字符串插值 → extractTemplateLiterals 解析出 quasis/expressions
```

**插值识别**（`walkInterpolation`）：
```js
// {{ $t('key') }} → isAlreadyTranslated → 跳过（防重复处理）
// {{ '中文' }} → 提取字符串中的中文 → { type: 'interpolation' }
```

**模板字符串解析**（`extractTemplateLiterals`）— 关键算法：

```js
// 输入: `共${total}条记录`
// 正则: /`([^`]*)`/ 匹配整个模板字符串
// split(/\$\{([^}]*)\}/) 分割:
//   parts = ['共', 'total', '条记录']
// 偶数索引 → quasis（静态文本），奇数索引 → expressions（插值表达式）
// 产出: { quasis: ['共','条记录'], expressions: ['total'] }
// 每个含中文的 quasi 单独产出结果，带 quasiIndex 标记
// 供 replacer 整体重建模板字符串
```

### 5.3 `script-parser.cjs` — 脚本 AST 解析

**技术**：`@babel/parser` + `@babel/traverse`

```js
ast = parser.parse(code, {
  sourceType: 'module',
  plugins: ['decorators-legacy', 'typescript', 'jsx'],  // decorators-legacy 必须有，否则 .ts 装饰器静默失败
  errorRecovery: true,   // 解析错误不抛异常，尽量恢复
})
```

**两条独立路径**：

#### 路径 1：VariableDeclarator 正向匹配（scriptTargets 配置驱动）

```
变量名命中 scriptTargets？
  ├─ 否 → 跳过（正向匹配：不在配置中的变量不翻译）
  └─ 是 → 检查 init
      ├─ 非 ref/reactive 的 CallExpression / AwaitExpression → 跳过（接口数据）
      ├─ 属性白名单（target = ['label','title']）
      │    → collectByProperties: 递归找对象，属性名匹配才提取中文
      └─ 全量翻译（target = []）
           → collectAllChinese: 递归遍历所有节点收集中文
```

**Vue 响应式展开**（`unwrapVueReactive`）：
```js
// ref({ label: '中文' }) → { label: '中文' }
// reactive({ ... }) → { ... }
// computed(() => '中文') → '中文'
// computed(() => { return expr }) → expr（展开 getter 函数体）
```

**ClassProperty 访问器**（Vue 2 class 组件）：
```js
// class Foo { columns = [{ label: '中文' }] }
// 处理 class 属性声明，与 VariableDeclarator 逻辑一致
// Vue 3 <script setup> 中不存在 ClassProperty，无副作用
```

**递归收集**（`collectAllChinese` 支持的类型）：
- `StringLiteral` → 提取中文
- `TemplateLiteral` → 无插值提取文本；有插值产出 template-literal 类型（含 quasis/expressions/模板起止列号）；多行插值产出 special
- `BinaryExpression (+)` → 递归提取所有中文字符串操作数
- `ConditionalExpression` → 递归 consequent / alternate
- `ObjectExpression` → 递归所有属性值
- `ArrayExpression` → 递归所有元素

#### 路径 2：translateMethods 白名单（方法调用参数）

`StringLiteral` 访问器跳过规则（优先级从高到低）：
1. import/export 声明中的字符串 → 跳过
2. 成员表达式赋值右值（`form.status = '中文'`）→ 跳过
3. 字符串拼接操作数（由 BinaryExpression 统一处理）→ 跳过
4. 对象 key → 跳过
5. TS 类型注解 → 跳过
6. 变量声明中的字符串（由路径 1 处理）→ 跳过
7. 不在函数调用参数中 → 跳过
8. 方法名不在 translateMethods 白名单 → 跳过

**通配符匹配**（`isTranslatableMethodArg`）：
```js
// 'ElMessage.*' 匹配 ElMessage.success / ElMessage.warning / ...
// getFullMethodName: 递归拼接 a.b.c 形式，支持 this.$message.error
```

## 六、替换器 — `replacer.cjs`

### `replaceInFile(filePath, items, reverseMap, scriptReactive, vueVersion)`

**替换总原则：从后往前、按行分组、列号定位**

#### 为什么从后往前？

```js
// 错误示范：从前往后
// 第 3 行替换后长度变化 → 第 10 行的行号偏移 → 替换错位置
// 正确：先替换第 10 行，第 3 行行号不受影响
const lineNums = Object.keys(byLine).map(Number).sort((a, b) => b - a)
```

#### 为什么按行分组？

同一行可能有多个中文，先按 `line - 1` 分组到 `byLine`，再逐行处理。同一行内**按中文文本长度降序排列**——短文本先替换会导致长文本的 indexOf 匹配失败（如 `"确定"` 先被替换后，`"确定删除吗"` 就找不到了）。

#### 列号定位

```js
// AST 提供 col（列号），优先用列号精确切片匹配
if (line.slice(item.col, item.col + item.chineseText.length) === item.chineseText) {
  idx = item.col  // 列号匹配成功 → 精确定位（避免同行相同中文命中错误位置）
} else {
  idx = line.indexOf(item.chineseText)  // 回退：源码可能已变更
}
```

#### 各类型替换模板（`buildReplacement`）

| 类型 | 原文 | 替换后 | 说明 |
|------|------|--------|------|
| static-attr | `label="中文"` | `:label="$t('key')"` | 整属性替换，支持跨多行属性值 |
| dynamic-attr | `:label="'中文'"` | `:label="$t('key')"` | 去掉外围引号 |
| interpolation | `{{ '中文' }}` | `{{ $t('key') }}` | 去掉外围引号 |
| text-content | `<span>中文</span>` | `<span>{{ $t('key') }}</span>` | 包插值 |
| script-string (Vue 3) | `'中文'` | `$t('key')` | 去掉引号 |
| script-string (Vue 2) | `'中文'` | `this.$t('key')` | Vue 2 用实例方法 |

#### 模板字符串整体重建

`template-literal` 类型不逐个替换，而是**整个模板字符串重建**：

```js
// 原: `共${total}条记录，请选择${name}`
// quasis: ['共', '条记录，请选择', ''], expressions: ['total', 'name']
// 重建: `${$t('key1')}${total}${$t('key2')}${name}`
// 算法：遍历 quasis，有 key 的 quasi 替换为 ${$t('key')}，
//       无 key 的保留原文，表达式原样插回
```

#### computed 包裹（`wrapWithComputed`）

`scriptReactive: true` 时对纯文本 const 变量包裹 `computed(() => ...)`：
```js
// const columns = [{ label: '中文' }]
// → const columns = computed(() => [{ label: $t('key') }])
// 仅处理: isConst && isPlainValue && !isComputed
// 从后往前处理避免行号偏移，按 varName 去重
// 支持单行和多行 init 表达式
```

#### import 自动注入（`injectImports`）

替换完成后检查并注入：
```js
// 1. 检测文件是否用了 $t( → 没有 import { $t } 则注入
//    import { $t } from '@/locales'
// 2. 检测文件是否用了 computed( → 没有 import 则注入
//    import { computed } from 'vue'
// 注入位置:
//   .vue → <script> 标签内最后一个 import 之后（skipToImportEnd 处理多行 import）
//   .ts/.js → 最后一个 import 之后，没有 import 则文件顶部
```

## 七、翻译器 — `translator.cjs`

### `translateViaAI(config, projectRoot)` 主流程

```
[1/4] 扫描文件提取中文 → 去重 → 过滤特殊类型
[2/4] 加载已有翻译：
      - 本项目 zh-CN.json 反向映射
      - 参考语言包（referenceLocales）合并（本项目优先）
      - 过滤已翻译 → untranslated
      - 检测翻译缺口（zh-CN 有 key 但目标语言缺翻译）
[3/4] AI 翻译：
      - 3a 新文本分批翻译（每批 batchSize 条，默认 200）
      - 3b 缺口补齐（按缺失语言组合分组，填空式翻译）
[4/4] 写回语言包：
      - 写入 zh-CN.json（中文 → key 映射）
      - 写入各目标语言 JSON
      - 未匹配项写日志
```

### AI 提示词设计（核心策略）

**新文本翻译**（AI_SYSTEM_PROMPT）——返回 `{ "中文原文": { "key": "module.camelCase", "en": "翻译" } }`：
- 顶层 Key 必须一字不改使用中文原文（字符级别一致，包括标点）
- 嵌套 key 用 camelCase 英文，AI 推断模块名（common/validation/placeholder/flow/status 等）
- 严格输出纯 JSON，禁止 Markdown 包裹

**缺口补齐**（AI_GAP_SYSTEM_PROMPT）——填空式：
- 给 AI 一个 key 结构模板，空字符串填翻译
- 严格保持 JSON 结构，只填空不改 key

### `parseAiResponse(content)` — 容错解析

```js
// 1. 直接 JSON.parse
// 2. 提取 ```json ... ``` 代码块再解析
// 3. 找第一个 { 到最后一个 } 切片解析
// 全部失败 → 返回 {} 并警告
```

### `validateAndRetryGapBatch` — 校验 + 重试

```
  → 有缺失 → 把缺失 key 列表附到下次 prompt 中重试
  → 3 次后仍失败 → 抛异常，该批标记失败
```

```js
// 递归遍历 zh-CN.json 所有叶子节点 → 得到 { fullKey, chineseText }
```

## 十一、核心原理总结

### 中文如何被识别？

```
正则 /[一-龥]/ 检测字符串是否含中文（CJK 统一汉字区间）
```

### 中文如何被定位？

```
1. AST 解析（@vue/compiler-dom 模板 / @babel/parser 脚本）
2. 每个 AST 节点自带 loc（行号、列号）信息
3. 行号 + 脚本块偏移 = 文件真实行号
4. 替换时优先用列号精确切片匹配，失败回退 indexOf
```

### 中文如何被替换？

```
1. 按文件分组 → 按行分组 → 从后往前（避免行号偏移）
2. 同行多中文按长度降序（避免短文本先替换破坏长文本）
3. 按类型生成替换文本（static-attr 整属性替换 / text-content 包插值 / script-string 去引号）
4. 模板字符串整体重建（quasis + expressions 重组）
5. 替换后自动注入 $t / computed import
```

### key 如何被匹配？

```
1. 读取 zh-CN.json → 构建反向映射 { "中文": "module.key" }
2. 扫描结果中的中文查反向映射
3. 命中 → 已匹配（替换为 $t('module.key')）
4. 未命中 → 未匹配（--translate 时 AI 生成 key，否则提示用户手动处理）
```

### Vue 2 和 Vue 3 的差异点

| 维度 | Vue 2 | Vue 3 |
|------|-------|-------|
| i18n 包 | vue-i18n@8 | vue-i18n v9+ |
| 实例创建 | `new VueI18n()` | `createI18n({ legacy: false })` |
| $t 导出 | `i18n.t.bind(i18n)` | `i18n.global.t` |
| 全局注册 | `Vue.prototype.$t` | `app.config.globalProperties.$t` |
| UI 库 | Element UI（`element-ui/lib/locale/lang/`） | Element Plus（`element-plus/dist/locale/*.mjs`） |
| 语言同步 | `elementLocale.use()` 手动切换 | watch + install 拦截自动同步 |
| script 替换 | `this.$t('key')` | `$t('key')` |
| translateMethods | `this.$message.*`（不区分 UI 库） | `ElMessage.*` / `Toast.*`（按 UI 库） |
| @vnet/i18n | 不需要 | 注入 getComponentMessages + setI18nInstance |
